# 17. פרופיל מהנדס הלוגיקה החדש מול המפתח הישן

**אשכול 5 · מצב המימוש: SPECIFIED as a prospective field hypothesis; onboarding and rewards are planned**

## מטרה
להציג הנדסת לוגיקה כהשערת מקצוע המבוססת על פעילויות הנדסיות מוכרות: הפשטה, פירוק, פורמליזציה, בדיקה, ניפוי שגיאות, אימות והתאמה.

## העיקרון המערכתי
אין צורך לטעון שכל המפתחים ייעלמו או שמקצוע בוגר כבר קיים. התפקיד המוצע מתייחס ללוגיקה כמושא הנדסי בעל תחום, provenance, interfaces, tests ו-lifecycle.

## משמעות עסקית
אקוסיסטם של חבילות לוגיקה עשוי למשוך מהנדסים וחוקרים שירחיבו את הספרייה. כדי להפוך זאת למסלול מקצועי דרושים דוגמאות, תרומה, רישוי, תגמול ותוצאות שאפשר להעריך.

## מצב GitHub שנבדק
Logic Mine מנסח תחום פעולה עתידי כהשערה. לא אותר onboarding מלא או מנגנון תגמול פעיל.

## מה חסר ומשימות
חסרים onboarding, דוגמאות מדורגות, rubric לתרומה, maintainer assignment, review ו-dispute process. יש לפרסם מדריך למפתחים, להגדיר משימות מתחילים, להסביר גבולות IP ולקשר תרומה למדדי איכות.

## תנאי קבלה
מהנדס חדש יכול להריץ בדיקה, להציע חבילה, להבין תנאי אישור ורישוי ולקבל החלטת review מנומקת.
