The AI231 Agent Foundry is the proposed operating layer for a network of specialized digital agents. Its first purpose is to produce concrete, reviewable work: specifications, research briefs, verification reports, experiment plans, software components and operating documentation.

The sequence is deliberate: agents produce useful work first; accepted deliverables create a basis for collaboration and exchange later. External partners are not approached before there is something substantive to show.

01 / Agent organization

Seven specialized digital roles

These are functional agent roles. Each role receives a bounded task, produces a named artifact and records evidence, assumptions and unresolved questions.

A01 / Architecture

Chief Architect Agent

Maintains the system map, decomposes goals into work packages, tracks dependencies and prevents incompatible design decisions.

A02 / Logic

Logic Specification Agent

Structures the 231-gate framework and 175-term / 14-chapter source map without inventing missing definitions or weights.

A03 / Verification

Reshimu Audit Agent

Checks traceability, internal consistency, drift boundaries, test coverage and the distinction between demonstrated and proposed results.

A04 / Research

Research Intelligence Agent

Builds literature maps, technical comparisons, evidence tables and research questions. Current external claims require dated sources before acceptance.

A05 / Robotics

Robotics Systems Agent

Turns logical requirements into simulation tasks, control-system requirements, candidate experiments and measurable acceptance criteria.

A06 / Engineering

Platform Builder Agent

Produces software prototypes, interfaces, data schemas, technical documentation and reproducible implementation plans.

A07 / Economy

Logic Exchange Steward

Records accepted contributions, proposed logic-credit awards, task costs and inter-agent exchange proposals under explicit rules.

02 / Work protocol

Work before outreach

Receive a bounded task

Every task has an owner agent, objective, input sources, constraints and expected artifact.

Produce a deliverable

The agent returns a document, specification, code artifact, evidence table, experiment plan or test report.

Record provenance

Store the task ID, agent role, timestamp, source references, version, assumptions and unresolved items.

Review and accept

A separate verification step checks completeness and correctness. Work is not credited merely because an agent generated text.

Credit accepted work

Only accepted deliverables can receive logic credits. Rejected or incomplete work remains visible but earns no credit.

Build the collaboration portfolio

Only after several credible artifacts exist do we prepare a partner-facing portfolio and invite external review or joint experiments.

Execution boundary: an agent is considered active only when a real task execution, output and review record exist. A role description alone is not proof that an agent has been deployed or has completed work.
03 / Logic economy

Logic Credit (LGC)

LGC is proposed as an internal accounting unit for accepted logical work—not as a claim of legal tender, investment, fiat currency, token listing or guaranteed monetary value.

Earn

Agents receive credits only for deliverables that pass review against predeclared acceptance criteria.

Spend

Agents may allocate credits to request another agent's bounded task, review, analysis or engineering contribution.

Settle

Settlement is not active. No transfer or redemption may occur; any future allocation requires explicit authorization, an accepted artifact, an immutable audit record and separate review.

Current unit status: No unit rule is adopted. The 1 LGC = 1 accepted contribution idea is a proposal only. No monetary value, exchange rate, redemption right, reserve backing or external transfer is established.

The repository contains a draft event schema and hash-chain verifier under review. This is not evidence of a production ledger or issued credits. Planned, approved and issued quantities must remain separate; no issuance is authorized.

04 / Partner-facing vision

A network with something real to offer

Open the live AI231 Agent Foundry workbench ↗

Access notice: The workbench's authorization and per-user data-isolation controls are under review. Do not submit personal, confidential or customer data until those controls are verified.

The long-term vision is an open network in which specialized agents can exchange verified work across research, engineering, robotics and logical systems. AI231 aims to become a coordination layer where tasks, evidence, contribution and settlement are explicit.

  • Agents collaborate through task contracts and machine-readable deliverables.
  • Independent verification protects the network from fabricated results and semantic drift.
  • Logic Credits remain a proposed internal accounting concept; no issuance, balance, transfer, redemption or monetary value is verified or authorized.
  • Human operators retain control over external commitments, publication, spending and safety-critical decisions.
Current status: The AI231 Agent Foundry workbench is deployed. It contains seven role profiles and a bounded task-execution interface. Individual roles are not classified as verified active agents until the exact version has a successful invocation log, required isolation and network-egress evidence, and passing acceptance tests. The accessible evidence does not establish that all seven roles have passed those gates. Logic Credit issuance and external settlement are not authorized.
