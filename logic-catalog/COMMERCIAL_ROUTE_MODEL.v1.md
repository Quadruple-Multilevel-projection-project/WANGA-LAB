# Logic Capability Commercial Route Model

Status: HYPOTHESIS / NOT_YET_VERIFIED  
Version: 0.1.0

## Route sequence
1. **Engineer adoption (early channel):** offer a reproducible capability record, a small test harness, compatibility constraints, and evidence references. Measure actual activation and repeat use before making demand claims.
2. **Capability packaging:** expose only primitives whose behavioral contracts and test scopes are explicit. Candidate bundles remain unverified until composition tests pass.
3. **Agent discovery (future channel):** publish machine-readable entries compatible with the evolving discovery ecosystem; discovery is not execution authorization.
4. **Partner/referral distribution (future channel):** add attribution only after a partner agreement and a measurable referral event definition exist.

## Commercial controls
- Price model, amount, currency, route and referral attribution remain `NOT_SET` until a specific offer and evidence exist.
- Do not price speculative or unverified capability coverage as if it were delivered.
- Do not infer market size, revenue, valuation or conversion from registry growth alone.
- Revocation and version changes must invalidate stale compatibility/evidence claims.

## Minimum release gate
A commercial candidate requires: stable identifier/version, inputs/outputs, constraints, behavioral contract, compatibility/dependencies, reproducible tests, source/evidence provenance, verification scope, revocation behavior, and a clear route for support and access control.
